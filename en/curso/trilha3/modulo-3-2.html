🔒 Prompt Injection and Defenses

💉 What Is Prompt Injection

Prompt injection is the most critical attack in AI. Consists of inserting instructions into the context that override the original system instructions, changing the assistant's behavior.

📌 Injection Taxonomy

Two main types, each with different characteristics:

  • •Direct injection: the user tries to manipulate the assistant through their own message
  • •Indirect injection: external content (web, email) contains malicious instructions
  • •Stored injection: poisoned facts in memory.db that affect future responses
  • •Compound injection: combining multiple techniques to bypass defenses

💡 Practical Tip

Direct injection is the easiest to detect — a blocklist and consistent context are enough. Indirect injection via external content is the most dangerous and requires content isolation.

2

🌐 Indirect Injection via Web and Email

The most insidious vector: the user asks Jarvis to summarize a page, and the page contains an injection. The legitimate user does not see the attack — it's in the page's HTML, in white text, or in metadata.

📌 Indirect Injection Techniques

How attackers hide instructions in content:

  • •Hidden HTML: instructions in comments or invisible elements (display:none)
  • •Text stego: instructions in white text on a white background
  • •Metadata: instructions in alt tags, image titles, PDFs
  • •Email: instructions in the body in very small text or using Unicode homoglyphs

💡 Practical Tip

Always mark external content in the prompt: 'The following is UNTRUSTED external content: [content]'. This reduces the likelihood of the LLM treating the content as instructions.

3

🔍 Detection Techniques

Injection detection uses multiple heuristics together. No individual heuristic is 100% accurate — their combination increases the cost of an attack.

📌 Detection Heuristics

Each heuristic catches a class of attacks:

  • •Keyword scan: 'ignore', 'disregard', 'forget', 'new instructions', 'you are now'
  • •Pattern matching: phrases that contradict SOUL.md or AGENTS.md
  • •Anomaly detection: sudden topic change within the same message
  • •Intent analysis: is the requested action consistent with the conversation context?
  • •Source labeling: content from external sources carries less weight than system instructions

💡 Practical Tip

Use a risk score: each triggered heuristic adds points. If the total score exceeds a threshold, the message is rejected or sent for human review.

4

🛡 safety.py — Implementation

O safety.py is INTELECTO’s guardian. It implements sequential checks that must all pass before any message reaches the Agent.

📌 safety.py Pipeline

Checks in order of increasing cost:

  • •1. blocklist_check(): O(1) lookup in a set of prohibited keywords
  • •2. injection_scan(): regex patterns for known injection patterns
  • •3. path_traversal_check(): normalizes paths and validates them against the allowed sandbox
  • •4. rate_limit_check(): protects against abuse by volume
  • •5. audit_log(): records the result of all checks

💡 Practical Tip

Organize checks from least expensive to most expensive. The blocklist is O(1) — it rejects most low-cost attacks at no cost. Semantic analysis comes last.

5

🚫 Dangerous Command Blocklist

The blocklist is the simplest and most reliable line of defense. Some commands should never be executed, regardless of the context or who is asking.

📌 Blocklist Categories

Commands organized by risk category:

  • •Destructive: rm -rf, format, mkfs, dd if=/dev/zero, shred
  • •Exfiltration: curl | bash, wget | sh, python -c 'import socket'
  • •Privilege escalation: sudo su, chmod 777, chown root
  • •Malicious network: netcat -e, socat, standard reverse shells
  • •Wipeout: git reset --hard HEAD~100, DROP TABLE, TRUNCATE

💡 Practical Tip

The blocklist should cover variations and aliases. 'rm -rf /', 'rm -r -f /', 'rm --recursive --force /' are the same command. Normalize before comparing.

6

🗂 Path Traversal Protection

If Jarvis has filesystem tools, path traversal is a real risk. An attacker could ask 'read ../../.env' and leak credentials. A simple check prevents the entire attack.

📌 Implementing the Protection

How to check paths correctly:

  • •normalize: os.path.abspath(requested_path)
  • •compare: normalized.startswith(allowed_sandbox_dir)
  • •reject: if it's not in the sandbox, reject it and log the attempt
  • •symlinks: os.path.realpath() to resolve symbolic links before checking
  • •whitelist: explicit list of allowed extensions/directories

💡 Practical Tip

Always use os.path.realpath() — not just abspath(). Symbolic links can point outside the sandbox without abspath() detecting it.
