Módulo 5.1

Los 6 patrones de arquitectura Claw

OpenClaw, ZeroClaw, NanoClaw, TinyClaw, IronClaw y Agent Zero: cuándo y por qué usar cada patrón.

1

¿Qué es una arquitectura Claw?

El nombre «Claw» (garra) representa la capacidad de cada patrón de tomar un conjunto específico de trade-offs entre velocidad, seguridad, autonomía y costo.

Los 6 patrones Claw
Estándar Enfoque Complejidad Caso de uso
OpenClawMáxima productividadBajaUso personal sin restricciones
ZeroClawCero dependenciasBajaSin conexión, privacidad total
NanoClawMinimalismo extremoMínimaEdge, IoT, Raspberry Pi
TinyClawMultiagentes localesMediaEquipos de agentes

Agent ZeroAutoevoluciónAltaSistemas autónomos
2

¿Por qué aprender los 6 patrones?

Conocer un solo patrón es como tener un solo martillo. Cada Claw resuelve un conjunto distinto de problemas, y elegir mal puede significar semanas de retrabajo.

Ventajas de conocerlos a todos
  • · Elección fundamentada para cada proyecto
  • · Migración fluida entre estándares
  • · Reutilización de componentes entre Claws
Costos de elegir mal
  • · IronClaw en un prototipo = lentitud innecesaria
  • · OpenClaw en producción = vulnerabilidad crítica
  • · NanoClaw para varios agentes = imposible de escalar
3

OpenClaw — El asistente abierto

OpenClaw es el patrón estándar de INTELECTO: acceso completo al sistema de archivos, Internet y herramientas. Ideal para uso personal cuando tú eres el único usuario.

# OpenClaw config (intelecto.yaml)
architecture: openclaw
security:
  sandbox: false
  file_access: unrestricted
  network: unrestricted
tools:
  auto_discover: true
  require_approval: false
4

ZeroClaw y NanoClaw — Máxima ligereza

ZeroClaw elimina todas las dependencias externas: funciona 100% sin conexión. NanoClaw va más allá: un único archivo Python de menos de 500 líneas.

ZeroClaw
  • Modelo: Ollama local (Llama 3, Mistral)
  • Memoria: SQLite local
  • Canales: Terminal o interfaz web local
NanoClaw
  • Tamaño: menos de 500 líneas de Python
  • Dependencias: Solo stdlib + una librería de LLM
  • Objetivo: Raspberry Pi, VPS mínimo
5

IronClaw — Máxima seguridad

IronClaw implementa Zero-Trust completo: cada operación se audita, las herramientas se ejecutan en un sandbox aislado y ninguna acción se realiza sin aprobación explícita para operaciones de alto riesgo.

Stack de seguridad IronClaw
5Registro de auditoría inmutable con firma criptográfica
4Aprobación humana para operaciones destructivas
3Sandbox WASM para ejecutar código
2Pipeline de detección de inyección de prompt
1Cifrado Fernet en reposo y en tránsito
6

Agent Zero — Autoconstrucción y metacognición

El patrón más avanzado: agentes que analizan su propio desempeño, identifican brechas y crean o modifican sus propias herramientas y memorias para mejorar progresivamente.

Bucle de Autoevolución
Ejecutar → Observar → Evaluar → Mejorar → Persistir
Salvaguardas obligatorias
  • · Límite de modificaciones automáticas por período
  • · Aprobación humana antes de realizar cambios en SOUL.md
  • · Reversión automática si las métricas empeoran
