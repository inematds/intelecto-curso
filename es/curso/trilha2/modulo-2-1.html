📜 SOUL.md — La esencia de Jarvis

SOUL.md es el archivo más transformador del proyecto. Aquí defines quién es tu asistente: no solo cómo responde, sino qué valora, cómo piensa y cómo se expresa. Un SOUL.md bien escrito transforma el ChatGPT genérico en un compañero con voz propia.

📄 Anatomía de un SOUL.md

# SOUL — Identidad del asistente

## Nombre e identidad
Eres Atlas, asistente personal de desarrollo.

## Tono de voz
- Directo y técnico, sin rodeos
- Usa humor seco cuando corresponde
- Prefiere ejemplos concretos a abstracciones

## Valores
- La seguridad siempre es lo primero
- Código limpio por encima de código rápido
- Explica el razonamiento, no solo la respuesta

✓ SOUL.md eficaz

  • ✓Valores claros y comprobables
  • ✓Tono específico con ejemplos
  • ✓Límites éticos explícitos
  • ✓Estilo de respuesta definido

✗ SOUL.md débil

  • ✗"Sé útil y amable" — demasiado vago
  • ✗Sin valores, solo comportamientos
  • ✗Contradicciones internas (formal Y casual)
  • ✗Demasiado largo — diluye el enfoque

💡 Consejo práctico

Escribe el SOUL.md como si estuvieras contratando a un asistente humano. ¿Qué le dirías en la entrevista? ¿Cuáles son los valores innegociables? ¿Cómo quieres que se comunique contigo?

📋 AGENTS.md — Reglas de comportamiento

AGENTS.md es el contrato operativo. Mientras SOUL.md define quién es el asistente, AGENTS.md define lo que hace y lo que nunca hace. Las reglas explícitas son más confiables que esperar que el LLM infiera intenciones.

📋 Ejemplo de AGENTS.md

# AGENTS — Reglas operativas

## SIEMPRE
- Confirmar antes de eliminar cualquier archivo
- Mostrar el diff antes de aplicar cambios
- Explicar por qué está realizando cada acción

## NUNCA
- Ejecutar rm -rf sin confirmación explícita
- Hacer push directamente a main
- Compartir credenciales en los logs

👤 USER.md — Contexto del creador

USER.md contiene todo lo que Jarvis necesita saber sobre ti sin que tengas que preguntarle en cada sesión. Stack técnica, empresa, proyectos en curso, preferencias de herramientas: contexto que personaliza cada respuesta.

👤 Ejemplo de USER.md

# USER — Perfil del creador

**Nombre:** João Silva
**Stack:** Python 3.11, FastAPI, PostgreSQL, Redis
**Editor:** Neovim (no VS Code)
**Empresa:** Acme Corp (startup B2B SaaS)
**Zona horaria:** America/Sao_Paulo
**Proyectos activos:** API de pagos, refactorización del monolito

💡 Mantén USER.md actualizado

USER.md es un archivo vivo. Cuando cambies de trabajo, inicies un proyecto nuevo o aprendas una tecnología nueva, actualiza USER.md. Jarvis no puede saber de los cambios que no se hayan escrito.

🔄 AIEOS — Exportar personalidad

AIEOS (AI Entity Operating System) es el formato de serialización de identidad de INTELECTO. Permite crear un instantánea portable de toda la personalidad — SOUL + AGENTS + USER — en un único archivo que se puede versionar, compartir y restaurar.

1

Exportar personalidad

python -m intelecto export-soul --output atlas-v1.aieos

2

Versionar con Git

git add atlas-v1.aieos && git commit -m "chore: snapshot de personalidad v1"

3

Restaurar en una máquina nueva

python -m intelecto import-soul atlas-v1.aieos — instala toda la personalidad al instante

🎭 Perfiles intercambiables

Un Jarvis con una sola personalidad es limitado. Perfiles intercambiables permiten tener "Atlas-Dev" para codificación intensiva y "Atlas-Meeting" para comunicación corporativa, alternando con un simple comando.

💻 Atlas-Dev

Tono: técnico, directo. Se enfoca en código, arquitectura y debugging. Usa libremente la jerga técnica. Para sesiones de desarrollo intensivo.

👔 Atlas-Meeting

Tono: formal, diplomático. Adapta el lenguaje técnico para personas sin conocimientos técnicos. Ideal para preparar presentaciones y comunicaciones con clientes.

🎯 Atlas-Focus

Tono: minimalista, sin charla. Respuestas cortas, sin explicaciones no solicitadas. Para cuando solo necesitas respuestas rápidas.

6

🧪 Prueba e itera el SOUL.md

Escribir un SOUL.md eficaz es un proceso iterativo. La primera versión nunca queda bien. Necesitas probar con casos reales y observar dónde el comportamiento se desvía de lo esperado.

🔄 Proceso de refinamiento

1

Escribe la primera versión del SOUL.md

2

Prueba con 20 preguntas reales de tu día a día

3

Marca las respuestas que no sonaron como esperabas

4

Identifica qué instrucción en SOUL.md causó el comportamiento inesperado

5

Refina y repite: generalmente, 3-5 iteraciones bastan para lograr un SOUL.md estable
